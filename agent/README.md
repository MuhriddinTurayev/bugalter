# Bugalter desktop agent

A small Node.js program for the accountant's **Windows** computer. It drives a **real, visible Edge/Chrome window**
on the official <https://my.soliq.uz>, signs in with the **official E-IMZO app** the way a person does, and does what
Bugalter (Laravel) tells it to: read the cabinet, or file one report the owner approved.

It is browser automation, not an API integration. It needs no Soliq API.

## What it never does

- It never sees, reads, copies or sends the ERI key (`.pfx`) or its password. E-IMZO holds the key; the accountant types
  the password in E-IMZO's own window. The agent only waits and reports "waiting for you".
- It never decides anything. Laravel queues the work, re-checks every hard-stop gate, and compares what the agent read back
  from the filled form with the approved report. If the numbers differ, the agent is told **not to sign**.
- It opens only `soliq.uz` (other hosts are blocked in the browser), and only the `https://my.soliq.uz` address built into the code.
- It does not bypass a CAPTCHA, a second factor or a security prompt. It pauses and asks the accountant (Tax → Agent shows what it waits for).
- It never repeats a submission. After Laravel allowed signing, any failure or silence means *outcome unknown*, which Laravel
  verifies against the cabinet and never resends blindly.

## Install (once)

Requirements: Windows, Node.js 20+, Microsoft Edge or Google Chrome, E-IMZO installed and running.

```powershell
cd agent
npm install
npm run doctor      # checks E-IMZO, the browser and the key folder; prints no key names or contents
```

In Bugalter: **Platform panel → Integrations → gateway: "agent"**. Then, as the company owner, **Tax → Agent → Connect a
computer**. Copy the key shown there (it is shown once and only its hash is stored), then:

```powershell
npm run setup       # server address + agent key; the key is stored encrypted with Windows DPAPI for this user
npm start           # keeps asking Bugalter for work; Ctrl+C to stop
```

Revoke a computer on the same page at any time; its token stops working immediately and its open tasks stop.

## What is verified and what is not

Observed live on 2026-10-24 with Edge, E-IMZO v4 and an **individual's** key (the accountant signed in by hand; the agent only read):

| Fact | How |
|---|---|
| Login: E-IMZO over `wss://127.0.0.1:64443`, key cards, tabs, "Кириш" | recorded; `src/login.js` |
| Sign-in works with the accountant's own steps (key, E-IMZO password) | `npm run discover`, 40 pages read, 0 problems |
| The signed-in taxpayer's identifier is in `[class*="Header_userIdentifier"]` (14 digits for an individual) | `cabinet-map.json` `identity` |
| That cabinet offers ONE declaration: the individual's annual income declaration (`/remotes-services/declaration/`, history at `.../history`, fields `pinfl, reportType, year, period, ...`) | `cabinet-map.json` `services` |
| Company reports (VAT, profit, turnover, payroll) are not in an individual's cabinet; they are filed through `oldmy.soliq.uz` (wefo4-clientui), another application | link targets seen on the services pages |
| The history table's headers (`ID рақами, Йил, Ҳисобот тури, Юборилган сана, Ҳолати, ...`); it had no real rows for this account | read; `src/tables.js` reads columns by header text |

### The e-reporting system (observed live, `npm run reporting`)

Clicking the service card on `my.soliq.uz/with-sidebar/services` opens **`oldmy.soliq.uz/wefo4-clientui`** in a new tab (an
informational notice with only a close button may cover the redirect page first; the agent closes such notices and nothing else).

| Observed | Where |
|---|---|
| Journal at `/wefo4-clientui/form/ru/reports/0`; panes `#div_{processing,error,approved,sent,rejected,draft,scheduled}_reports`, all in the DOM; columns `№ Отчета, Наименование, Год, Период, Дата отправки, Состояние, ...` | `src/journal.js`, tested in a real browser against that markup |
| This account has 6 accepted reports "Расчет налога с оборота" (form `10190_14`), monthly, state "Проведенный с опозданием" | journal |
| Catalog of forms, per tax (`/catalog/ru/get/packages/101` = turnover: `10190_14, _13, _11, _10`) | `cabinet-map.json` |
| The blank form `10190_14` opens **without** creating a draft (drafts 0 → 0); it has "Сохранить" (save) and "Отправить" (send) as separate buttons, hidden fields `xml_report_pkcs7`, `is_draft`, `report_id`, and a spreadsheet-style table instead of one input per cell | `reporting.json` |
| For individual entrepreneurs the system says this return is **generated by the tax authority** ("автоматизирован со стороны налоговых органов"); a correction goes through "Изменить" | notice on the form |

`task portal_check` now does the real thing: sign in → read the identifier the cabinet shows → compare with the company's STIR
or PINFL → open the e-reporting system → read every journal pane → Laravel normalises and compares with the books. Checked
end to end on 2026-10-24 (Laravel queue → agent → Edge → real cabinet): sign-in worked and the agent **stopped at the identity
check** because company `demo1` has neither this STIR nor this PINFL. Nothing was read or filed.

**Not observed, therefore not implemented as working:** the legal-entity entry (`user_type=2`), how cells of the form are
edited, the form's validation messages, the sign/send flow and result screen, the receipt number on the confirmation page,
quarterly period wording, VAT/payroll form names. `cabinet-map.json` lists them in `reporting.not_observed`.

Why no report is filed from this account: the only form it has that matches a Bugalter report type is the turnover return, which
the tax authority generates itself for entrepreneurs; its three monthly returns are already accepted and the next period
(October) is still open. The agent does not invent values and does not file "to test".

To continue: enter the entrepreneur's PINFL (Settings → company) on the Bugalter company that keeps this taxpayer's books, or sign in with
the key of a company, then run a cabinet check from Tax → Agent. For specific pages only:
`npm run discover -- legal /path1 /path2`. Output (UI words only, digits masked, plus screenshots that stay on this
computer) is written to `%APPDATA%\bugalter-agent\discovery`.

## Tests

`npm test` covers the parts that need no browser: money parsing (integer tiyin, no floats), key-card matching by TIN,
the server-address rules, and reading cabinet text as data. The Laravel side (queue, form check, unknown outcomes, leases,
verification) is in `tests/Feature/DesktopAgentTest.php`.

## Final confirmation

After the agent fills the cabinet form it stops and waits. The Tax → Agent page shows the values it read from the form and the
question "Topshirilsinmi?". "Yes" lets it sign (you confirm in E-IMZO) and send; "No" sends nothing. Nothing is signed or sent
without that answer.
